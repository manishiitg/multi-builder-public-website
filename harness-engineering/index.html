Harness engineering

Harness engineering for your company. Not one agent on one laptop.

An AI agent is a model plus a harness: the instructions, tools, checks and records around it. The model decides how well it can think. The harness decides whether it does the job every day. AgentWorks is where your company builds, shares and improves that harness, so the agents your people already use work the same way for everyone.

The six parts

Every part of a harness. Already in one place.

Agent failures often are not the model. They are a missing tool, an unclear instruction, no check on the result, or no record of what happened. These are the parts that prevent them, and where each one lives in AgentWorks.

PartWhat it isIn AgentWorks
Instructions and contextWhat the agent is told and what it can look up: its job, the rules, the know-how, and what happened last time.Project and per-agent instructions, skills, shared company knowledge in Brain, and memory that carries from one run to the next. Brain →
ToolsWhat the agent can act with, and how each tool explains itself so the agent uses it correctly.MCP servers, a browser, files, the database, Gmail, Slack and WhatsApp, granted per group through Vault. Vault →
The work loopHow the work runs: which steps need judgment, which are the same every time, and what starts them.Goal steps (agent steps for judgment, scripted steps for known work), Crews you can ask any time, schedules and condition triggers. Goals →
GuardrailsWhat the agent may touch, and what waits for a person.Access per group, secrets that reach work only as environment variables, step-level file access, and people approving the steps that matter. Vault →
ChecksHow you know a run did its job, not just that it finished.Output checks on every step, a goal with a number and a target, and a review of every run against them. Goals →
RecordsThe evidence: what was asked, what the agent did, what it cost and who approved it.Every run recorded with its steps, results, cost and the person who asked or approved, visible to the people the work is shared with. Product →

One person or the whole company

Harness engineering often stops at one laptop. Yours doesn't have to.

Claude Code, Codex and Cursor are excellent harnesses for one person. AgentWorks is the shared one for the company, built around the agents your people already use.

One engineer's harness

  • Instructions and skills live in one person's folders
  • Tools and keys sit on their machine
  • It runs when they start it
  • Checks are whatever they remember to do
  • No shared record of runs or cost

Your company's harness on AgentWorks

  • Instructions, skills and knowledge shared in one place
  • Tools and secrets granted per group, never copied around
  • Runs on a schedule, on a trigger, or when anyone asks
  • Every step checked, every goal measured against its target
  • Every run recorded: steps, result, cost and who approved

Example

A refund review, seen as a harness. Illustrative.

  1. Script pulls yesterday's refund requestsA tool call with no AI in the loop: the same result every time, checked before the next step starts.
  2. An agent checks each one against the orderIts instructions and the refund policy skill tell it what a valid request looks like.
  3. A rule in code flags anything over $200A guardrail that does not depend on the agent remembering it.
  4. A person approves the big onesIn Slack or WhatsApp, with the agent's reasoning attached.
  5. Script issues the refunds and records the runEvery refund, approval and cost lands in the run record, and the goal tracks how fast refunds close.

FAQ

Questions, answered.

What is harness engineering?

An AI agent is a model plus a harness: the instructions, tools, work loop, guardrails, checks and records around the model. Harness engineering is designing that layer so the agent does the job reliably, not just once in a demo.

Is AgentWorks an agent harness?

Yes, for a company. It runs on the coding agents and AI plans your people already use (Claude Code, Codex, Cursor and others) and adds the shared parts: company knowledge, granted tools and secrets, approvals, checks and a record of every run. It connects those agents rather than replacing them.

Do I need an engineer to do harness engineering on AgentWorks?

No. You describe the change to the Builder in plain words and it updates the steps, instructions and checks, with every change logged. Developers can make the same changes over MCP from their own coding agent.

How is this different from building an agent on my laptop?

On a laptop the harness belongs to one person: it runs when their laptop is on, uses their keys and leaves no shared record. On AgentWorks the same agent runs on a schedule or when someone asks, the team uses it from Slack, WhatsApp, a dashboard or their own AI, and every run is recorded.

Which AI models does it use?

It runs on the Claude, ChatGPT, Gemini or Cursor plan the company already pays for. The harness stays the same when you change the model.

Can I compare two versions of a harness?

Not with a built-in A/B switch yet. You can try a change, compare the measured results of runs before and after, and see exactly what changed in the plan's change log.
